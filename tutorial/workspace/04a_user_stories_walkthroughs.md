# Input for Part C: Sam's user stories and walkthrough notes (W1-W4)

> **Note to the instructor: simulated research.** I wrote the user stories for the persona I chose
> in Part B. For the walkthroughs, I used an AI agent to role-play four restaurant managers trying a
> clickable prototype of the tablet. The walkthrough notes are simulated.

## User stories for Sam, the Short-Staffed Night Manager

| ID | Story |
|---|---|
| US-01 | As Sam, I want new orders to get my attention even when I am away from the counter, so that no order times out. |
| US-02 | As Sam, I want to accept or reject an order in one step, so that I can get back to the floor quickly. |
| US-03 | As Sam, I want to set a preparation time when I accept, so that the rider and the customer know when the food is ready. |
| US-04 | As Sam, I want to mark a dish as unavailable myself, so that customers cannot order what we no longer have. |
| US-05 | As Sam, I want to pause new orders for a while at peak, so that the kitchen is not overloaded and we stay visible on the app. |
| US-06 | As Sam, I want to see each order's stage (accepted, preparing, ready, picked up), so that the kitchen and I share one view. |
| US-07 | As Sam, I want to see which orders are running late, so that I can act before the customer complains. |
| US-08 | As Sam, I want to confirm the right rider collects the right order, so that bags are not swapped. |
| US-09 | As Sam, I want to report a rider who does not arrive, so that the food does not wait and go cold. |
| US-10 | As Sam, I want to handle a missing-item complaint from the tablet, so that I do not spend minutes on the phone. |
| US-11 | As Sam, I want orders to keep coming in after a Wi-Fi drop, so that I do not lose orders. |

## Walkthrough notes

**W1: Linh (noodle restaurant)**
- Did not notice the new-order sound from the dining room; asked for it to keep repeating until accepted.
- Accept + prep time took two taps and one choice; she liked that.
- Wanted the rejection to ask for a reason so the owner can see why.
- Asked how long she has before an order is cancelled; the prototype did not say.

**W2: Dung (hotpot restaurant)**
- Marked "grilled squid" unavailable in under 10 seconds; wanted it to come back automatically the next day.
- Wanted to know which open orders already contain a dish he just marked unavailable.
- Pause button: asked for fixed durations, "15, 30 minutes or until I turn it back on" (durations to be confirmed with the product owner).

**W3: Hoa (rice restaurant)**
- Could not read the order list from two metres away; asked for larger order numbers and colour by stage.
- Wanted late orders to stand out; did not know what counts as "late".
- Rider handover: liked matching a short pickup code read out by the rider.

**W4: Thu (fried chicken franchise)**
- Wanted "rider not arrived" to be reportable after a waiting time (time not agreed).
- Missing-item complaint: wanted to refund one item rather than the whole order.
- During a simulated Wi-Fi drop, the prototype showed nothing; she wanted a visible "offline" state and no lost orders.
